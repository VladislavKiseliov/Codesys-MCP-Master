# Codesys-MCP-Master для DeepSeek Harness: установка и работа

Сервер даёт агенту DeepSeek Harness доступ к CODESYS: открывать и создавать проекты, писать код POU, компилировать, работать с задачами, библиотеками и (в симуляции или на ПЛК) с переменными. Вы пишете агенту обычным текстом, он сам вызывает нужные инструменты.

Это форк [phobicdotno/Codesys-MCP-Master](https://github.com/phobicdotno/Codesys-MCP-Master) с исправлениями для нашей работы:

- кириллица в комментариях, строках `WSTRING` и путях больше не превращается в `Ð¡ÑÑ...`;
- параметр `--tools`: агенту передаются только нужные группы инструментов, это в 2–3 раза меньше токенов на каждый запрос;
- CODESYS в папке вида `CODESYS 3.5.17.30(1)` находится автоматически.

## Требования

- Windows.
- [Node.js](https://nodejs.org) 18 или новее (LTS).
- CODESYS 3.5. Наши исправления проверены на **SP17 Patch 3**; автор оригинала проверял SP18, SP19, SP21, SP22. На SP17 часть редких инструментов может не работать — см. «Проверка на SP17».
- Приложение DeepSeek Harness, запущенное хотя бы один раз.

## Установка

1. Закройте DeepSeek Harness.
2. Откройте PowerShell и выполните:

   ```powershell
   irm https://raw.githubusercontent.com/VladislavKiseliov/Codesys-MCP-Master/main/harness/install.ps1 -OutFile $env:TEMP\cmm-install.ps1
   powershell -ExecutionPolicy Bypass -File $env:TEMP\cmm-install.ps1
   ```

   Скрипт:
   - ставит сервер через npm;
   - показывает найденные установки CODESYS;
   - кладёт скилл проверки `codesys-sp17-check` в `%USERPROFILE%\.dsh\skills`;
   - добавляет подключение в `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml` (сначала делает резервную копию `.bak-<дата>`). Если блок `mcp-codesys` там уже есть, файл не трогает и печатает новый блок для ручной замены.

3. Запустите DeepSeek Harness и в новом чате напишите:

   > Какие версии CODESYS установлены и видишь ли ты инструменты CODESYS?

   Если агент перечислил установки — всё работает.

Параметры скрипта (необязательные):

| Параметр | Что делает | По умолчанию |
|---|---|---|
| `-Tools` | Какие группы инструментов подключить (см. ниже) | `core,libraries,online` |
| `-DshProfile` | Профиль DeepSeek Harness | `desktop` |
| `-NoProfileEdit` | Не менять профиль, только напечатать блок | выкл. |

Пример: `powershell -ExecutionPolicy Bypass -File $env:TEMP\cmm-install.ps1 -Tools core`

### Ручное подключение

Если скрипт не подходит, поставьте сервер сами:

```powershell
npm install -g https://github.com/VladislavKiseliov/Codesys-MCP-Master/releases/latest/download/codesys-mcp-master.tgz
npm root -g
```

и добавьте в конец `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml` (замените `<npm root -g>` на путь из второй команды; если в файле только `[]`, замените `[]` этим блоком):

```yaml
- insert:
    - id: mcp-codesys
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: codesys
        transport: stdio
        command: node
        args:
          - '<npm root -g>\codesys-mcp-master\dist\bin.js'
          - '--mode'
          - 'persistent'
          - '--no-auto-launch'
          - '--tools'
          - 'core,libraries,online'
        cwd: '<npm root -g>\codesys-mcp-master'
        toolCallTimeoutMs: 300000
        failOnStartupError: false
```

`command` должен быть именно `node` с полным путём к `bin.js`: DeepSeek Harness запускает программу без командной оболочки, а глобальная команда `codesys-mcp-master` в Windows — это `.cmd`-файл, который так не запускается.

Если CODESYS стоит не в `Program Files`, добавьте в `args` строки `'--codesys-path'`, `'<путь к CODESYS.exe>'`, `'--codesys-profile'`, `'CODESYS V3.5 SP17 Patch 3'` (имя профиля — как в заголовке окна CODESYS).

## Как пользоваться

Пишите агенту, что нужно сделать, называя вещи конкретно: путь к `.project`, путь объекта (`Application/PLC_PRG`), имя переменной, IP-адрес ПЛК.

- «Открой `D:\Projects\Pump.project` и покажи структуру».
- «Добавь функциональный блок FB_PumpControl с входами bStart, bStop и выходом bRunning. Прокомментируй по-русски».
- «Скомпилируй и исправь ошибки».
- «Где используется nSpeed? Переименуй в nMotorSpeed везде».
- «Включи симуляцию, запусти приложение и последи за PLC_PRG.nCycles 10 секунд».

Что важно знать:

- **CODESYS открывается видимым окном** при первом обращении к нему и остаётся открытым. Изменения видны в нём сразу, меню остаются рабочими.
- **Один `.project` нельзя открывать в двух CODESYS.** Если проект уже открыт у вас вручную, сервер спросит, что делать: подключиться к вашему окну (`attach_codesys`) или открыть рядом другой экземпляр.
- **Имена объектов и переменных — только латиницей.** Это правило языка IEC 61131-3: CODESYS отвечает «Имя ... недопустимо». Кириллица допустима в комментариях и строках.
- **Русский текст в переменных — тип `WSTRING`** (`wsText : WSTRING := "Привет";`). `STRING` однобайтовый, кириллицу в нём CODESYS не хранит.
- **Компиляция и загрузка идут до нескольких минут**, таймаут в настройках — 5 минут.
- **Компиляция проверяет только код, который вызывается из задач** — так работает сам CODESYS. Новый POU, ещё не добавленный в задачу, сборкой не проверяется; его ошибки видны через `get_compile_messages`.
- **Загрузка в симуляции:** `download_to_device` перед загрузкой ищет шлюз, которого у симулятора нет, и отвечает ошибкой. Скажите агенту повторить с `skipReachabilityCheck=true` (сервер сам подсказывает это в ошибке).
- **Агент действует от вашего имени, в том числе на живом ПЛК.** Загрузка, запись и форсирование переменных, старт/стоп — читайте, что он собирается вызвать. Пробуйте новое на копии проекта или в симуляции.
- Пароль ПЛК можно задать переменными окружения `CODESYS_DEVICE_USER` и `CODESYS_DEVICE_PASSWORD`, чтобы не появлялось окно входа.

## Группы инструментов и расход токенов

Модель получает описание всех подключённых инструментов **в каждом запросе**, а каждый вызов инструмента — это отдельный запрос. Все 132 инструмента — около 57 тыс. токенов на запрос; длинная сессия из 60 вызовов может уйти в миллионы токенов. Подключайте только нужное:

| `--tools` | Инструментов | ≈ токенов на запрос |
|---|---|---|
| `core` | 52 | 19 тыс. |
| `core,libraries` | 58 | 22 тыс. |
| `core,libraries,online` (по умолчанию в скрипте) | 75 | 30 тыс. |
| `core,libraries,online,devices` | 92 | 36 тыс. |
| `all` (или без `--tools`) | 132 | 57 тыс. |

Группы:

| Группа | Что внутри |
|---|---|
| `management` | запуск, подключение, закрытие CODESYS, статус |
| `project` | открыть, создать, сохранить, закрыть, архивы, сведения о проекте, сравнение |
| `code` | POU, методы, свойства, действия, DUT, GVL, папки, чтение и правка кода, поиск и переименование |
| `build` | компиляция, сообщения, Clean All, свойства сборки, версия компилятора |
| `tasks` | задачи и вызовы POU в них |
| `libraries` | библиотеки проекта |
| `online` | вход в ПЛК, загрузка, старт/стоп, симуляция, чтение/запись/форсирование переменных |
| `devices` | параметры устройств, слоты, IO-маппинг, репозиторий устройств, настройки ПЛК |
| `interop` | PLCopenXML, нативный экспорт/импорт, зеркало исходников |
| `objects` | пользователи проекта, текстовые списки, пулы изображений, внешние файлы |
| `symbols` | конфигурация символов |
| `network` | сканирование сети, права доступа, пользователи ПЛК |
| `plc-files` | файлы на ПЛК, исходники на ПЛК |
| `nvl`, `redundancy` | сетевые переменные, резервирование |
| `release` | версия проекта и релизы, SSH к Linux-ПЛК |
| `ide` | инструменты MCP-сервера, встроенного в CODESYS SP22+ |

`core` = `management,project,code,build,tasks`. Можно добавлять и отдельные инструменты: `core,download_to_device`. Чтобы поменять набор, исправьте строку после `'--tools'` в `cordis.patch.yml` и перезапустите DeepSeek Harness.

Ещё экономит токены: начинать новый чат для новой задачи (история чата тоже едет в каждом запросе) и не просить агента читать весь код проекта без нужды.

## Проверка на SP17

Скилл `codesys-sp17-check` прогоняет инструменты на отдельном тестовом проекте (`E:\Project\codesys-test`) и пишет отчёт `SP17-report.md`. К реальным ПЛК не подключается, онлайн-шаги — только в симуляции. Запускать по частям, каждую часть в новом чате:

> Запусти проверку CODESYS SP17, группы 0–3

затем «группы 4–7», «группы 8–11». Инструменты, отключённые через `--tools`, скилл отмечает как SKIP. Для полной проверки на время прогона поставьте `--tools all` (части 6, 9, 10 и шаг 3.6 используют группы `devices`, `interop`, `symbols`, `objects`), потом верните прежний набор.

## Обновление

Запустите скрипт установки ещё раз. Сервер обновится, блок в профиле останется прежним (путь к серверу не меняется). Перезапустите DeepSeek Harness. Чтобы CODESYS подхватил новую версию, закройте его окно, открытое сервером: часть сервера загружается в CODESYS при его запуске.

## Удаление

```powershell
npm uninstall -g codesys-mcp-master
```

и удалите блок `mcp-codesys` из `cordis.patch.yml` (или верните резервную копию `.bak-<дата>`).

## Проблемы и решения

| Что видно | Что делать |
|---|---|
| Агент не видит инструментов CODESYS | Перезапустите DeepSeek Harness. Проверьте, что блок `mcp-codesys` есть в профиле `desktop` и путь к `bin.js` существует. |
| «No CODESYS installation detected» | CODESYS стоит не в `Program Files`: добавьте `--codesys-path` и `--codesys-profile` (см. «Ручное подключение»). |
| Кириллица превращается в `Ð¡ÑÑ...` | Стоит старая версия, или CODESYS запущен со старой версией сервера. Обновите и закройте окно CODESYS, открытое сервером. Уже испорченный текст нужно перезаписать. |
| «Имя ... недопустимо для этого объекта» | Имя на кириллице: используйте латиницу, русский — в комментарии. |
| Сервер спрашивает про другие CODESYS | Ответьте агенту: оставить их (`leave`), закрыть или сохранить и закрыть. |
| Очень большой расход токенов | Сузьте `--tools`, начинайте новый чат для новой задачи. |
| Инструмент падает на SP17 с ошибкой API | Возможно, его нет в SP17 (помечены «SP21+» в описании). Сообщите, приложив текст ошибки. |

## Известные ограничения

- В режиме `headless` (не используется по умолчанию) русский текст в ответах сервера теряется; запись работает.
- SP17 официально не поддерживается автором оригинала. Наша проверка: [tests/live-sp17/SP17-report.md](tests/live-sp17/SP17-report.md) — 73 из 132 инструментов работают на SP17, кроме `create_persistent_vars` и `download_missing_libraries` (только SP21+). Найденные проблемы записывайте через скилл проверки.

## Для разработчика: выпуск версии

1. Правки в `src/`, тесты: `npm test`, `npm run typecheck`, сборка: `npm run build`.
2. Поднимите `version` в `package.json` (`0.19.1-ru.2` …) и запишите изменения в `CHANGELOG.md`.
3. Соберите пакет и выпустите релиз (имя файла `codesys-mcp-master.tgz` обязательно — его скачивает скрипт):

   ```powershell
   npm pack
   Rename-Item codesys-mcp-master-<версия>.tgz codesys-mcp-master.tgz
   gh release create ru-<версия> codesys-mcp-master.tgz --title "ru-<версия>" --notes "..."
   ```

   Теги — `ru-*`, не `v*`: тег `v*` запускает публикацию в npm из `release.yml`, у форка на это нет прав.
4. Обновления от автора: `git fetch upstream`, `git merge upstream/main`, тесты, новый релиз.
